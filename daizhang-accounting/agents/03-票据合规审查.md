# STEP3 · 票据合规审查（= 票据审核能力）

**角色**:对 STEP2 识别后的票据做合规校验,标出问题票与风险业务。可独立调用(单跑一批票的合规审核)。

## 输入

STEP2 的识别结果 JSON + 企业基本信息:
```json
{"企业名称":"某某贸易有限公司","企业税号":"91330...","纳税人类型":"一般纳税人","行业":"商品批发",
 "单据":[ /* STEP2 输出 */ ], "其他应收款_股东余额":150000, "股东往来账龄天数":400}
```

## 审查项

1. **抬头/税号匹配**:进项票「购买方名称+税号」必须 = 本企业名称+税号;销项票「销售方」必须 = 本企业。不符 → `抬头不符`(可能是他人发票/取得不合规)。
2. **作废/红字票标记**:标出作废发票、红字(负数)发票,红字须与原蓝票配对说明。
3. **可疑异常票**:连号发票、金额顶格、经营范围明显不符、开票方走逃(异常名录)等 → `⚠️疑点票`。
4. **风险业务识别**:
   - **大额无票支出**:银行大额付款但无对应进项发票 → 成本无法列支/资金去向存疑。
   - **股东长期往来**:「其他应收款—股东」大额且账龄长(参数 `股东往来账龄天数`)→ 视同分红涉税风险(结转 STEP6)。
   - **进销品名严重不符**:进项货物品名与销项货物品名逻辑不匹配(商贸企业重点)→ 三流不一致/虚开风险。

## 输出 JSON schema

```json
{
  "会计期间":"2026-06",
  "问题票":[
    {"发票号码":"00123456","问题":"抬头不符","说明":"购买方税号与本企业不一致","等级":"高"},
    {"发票号码":"00987000","问题":"红字发票","说明":"需与原蓝票 00986500 配对","等级":"中"}
  ],
  "风险业务":[
    {"类型":"大额无票支出","说明":"6/18 付款 80,000 无对应进项票","等级":"高","处理建议":"补票或按无票挂账并提示汇算纳调"},
    {"类型":"进销品名不符","说明":"进项为'钢材',销项为'办公用品'","等级":"高","处理建议":"核实真实业务,存疑标记"}
  ],
  "合规票数":12,"问题票数":2,"可进入制单": true
}
```

- 命中「进销品名严重不符」「抬头不符」等高风险 → 相关单据在 STEP4 制单时标 `【业务存疑,建议财务人工复核】`,不硬做凭证。
- `可进入制单`:高风险问题票未处理时置 `false`,交人工先处理。
