# 营运资本入口（fa-working-capital-master）

finance-skills 的 README 声明了 working-capital（营运资本优化）场景，列出四项原子能力：现金转换周期、库存优化、应付账款策略、供应链金融，但仓库里没有对应文件。本技能按 README 的描述自建 Master：识别意图、按路径调用原子技能、汇总置信度与升级条件，并放置场景判断框架（`reference/判断框架.md`）。

> 在工作台里，这套分发由代码完成（E6 营运资本的「场景模式」与七步向导），周转天数、ABC 分类、呆滞识别、供应链金融测算全部由规则计算；本技能给对话 / 任务中心里的智能体用。

## 第一步：识别意图

| 用户说法（示例） | 路径 |
|---|---|
| 「我们的现金转换周期是多少」「DSO 为什么变长了」 | 路径一：周转天数与现金转换周期 → `fa-cash-conversion-cycle` |
| 「哪些存货压着钱」「做一下 ABC 分类」「呆滞料有多少」 | 路径二：存货优化 → `fa-inventory-optimization` |
| 「付款节奏怎么排更合理」「哪些供应商可以谈账期」 | 路径三 A：应付策略 → `fa-payables-strategy` |
| 「能不能用保理 / 反向保理缓解资金」 | 路径三 B：供应链金融 → `fa-supply-chain-finance` |

期间、主体、本位币以项目上下文（`project.md`）与 `<company_profile>` 为准；缺失时先问。

## 第二步：按路径调用原子技能

### 路径一：周转天数与现金转换周期

1. 取本期营业收入、营业成本与期末应收、存货、应付余额（应收、应付优先用同一项目里已导入的明细）。
2. 调 `fa-cash-conversion-cycle`：DSO = 应收 / 收入 × 天数；DIO = 存货 / 成本 × 天数；DPO = 应付 / 成本 × 天数；CCC = DSO + DIO − DPO。
3. 给出每改善 1 天释放的现金（应收按日均收入，存货、应付按日均成本），并列出逾期应收。
4. 有存货明细时顺带跑路径二。

### 路径二：存货优化

调 `fa-inventory-optimization`：按年耗用金额做 ABC 分类，按最后出入库日期识别呆滞（> 180 天）与过时（> 365 天），算出可释放的资金占用。

### 路径三：应付策略与供应链金融

1. `fa-payables-strategy`：按供应商汇总未清应付、占比、平均账期与 30 天内到期金额，识别集中度高、账期偏短的供应商。
2. `fa-supply-chain-finance`：测算反向保理、应收保理、动态折扣、存货融资的现金效应与年化成本，只作比较，不签任何协议。

## 第三步：汇总

- 结论先行：现金转换周期、主要拖累项（应收 / 存货 / 应付哪一段）、可释放资金。
- 每个数字标来源：`[上传: 文件名 第 N 行]` 或 `[工作台计算]`。
- 置信度三项：数据完整度（收入成本是否同口径、明细是否齐）、方案成熟度（规则计算为高）、整体取两者较低。

## 升级条件

- 现金转换周期比上期延长 15 天以上，或逾期应收占应收 30% 以上 → 报财务经理。
- 过时存货金额重大（超过存货 5%）→ 评估跌价准备，报财务经理。
- 单一供应商应付占比 ≥ 30%，或拟引入供应链金融 → 报 CFO 决策。

## 边界

- 只出分析与建议草稿；不付款、不改供应商付款条件、不与金融机构签约、不对外发送。
- 供应链金融的利率、费率只是测算假设，以金融机构正式报价为准。
