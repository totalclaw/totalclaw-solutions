# 费用报销稽核入口（fa-expense-review-master）

报销审核场景在源项目里没有 Master，本技能补上：识别意图、按路径调用原子技能、汇总结论与升级条件，并统一放置场景知识后端（`reference/判断框架.md`、`reference/数据源清单.md`、`reference/查询路径.md`）。

> 在工作台里，这套分发由代码完成（A5 费用报销稽核的「场景模式」与七步向导）：单票与整单预审只读复用财务智能体的规则，超标率分档、提交时限、ZATCA 二维码核对与异常模式由本方案规则引擎计算，模型不参与算数；本技能给对话 / 任务中心里的智能体用。单笔报销的实时审核在财务智能体「费用报销」里做。

## 第一步：识别意图

| 用户说法（示例） | 路径 |
|---|---|
| 「把 9 月的报销单批量过一遍」「事后稽核一下报销」 | 路径一：批量稽核 |
| 「看看有没有拆单、连号、同一张票报两次」 | 路径二：只扫描异常模式 |
| 「这张发票是真的吗」「沙特这张电子发票的二维码对不对」 | 转 `fa-invoice-verification` |
| 「差旅超标了怎么处理」 | 转 `fa-policy-compliance-check` |
| 「采购类报销要不要做三单匹配」 | 转 `fa-three-way-match` |

期间、主体、费用标准以项目上下文（`project.md`）与 `<company_profile>` 为准；缺失时先问。

## 第二步：按路径调用原子技能

### 路径一：批量稽核

1. `fa-invoice-verification`：逐张票据核对金额勾稽、税号校验位、抬头、重复票、开票日期；沙特电子发票解析 ZATCA 二维码（TLV：卖方、增值税号、时间、含税总额、增值税额），与票面逐项比对。
2. `fa-policy-compliance-check`：按城市、职级、天数算标准上限；超标率 ≤ 5% 轻微（直属上级确认）、5%–20% 上级加签、> 20% 初步驳回。
3. `fa-reimbursement-review`：六项必检（发票、标准、预算、审批、三单、期间归属）；提交距开票 ≤ 30 天正常、30–90 天须说明、> 90 天驳回。
4. `fa-three-way-match`：仅采购类报销。
5. `fa-dispute-identification`：跨单据二次扫描（见路径二）。

### 路径二：只扫描异常模式

`fa-dispute-identification` 的六个模式，外加本方案补的四个：

- 高频异常员工：同一员工同一自然月某一类异常 ≥ 2 次，或合计 ≥ 3 次 → 升级；
- 拆单 / 临界规避：同一员工同一供应商 30 天内 ≥ 3 笔且每笔低于审批阈值 → 升级；贴近审批边界（如 4,999）→ 抽查；
- 供应商集中：同一供应商 30 天内 ≥ 5 笔且合计达到门槛 → 升级；
- 跨期规律：提交距费用发生 ≥ 60 天的 ≥ 3 次 → 要求说明；
- 周末票据、整数金额、发票连号：只列出供抽查（源项目未给规则）；
- 同票多报：同一发票号（含代码）出现在多行 → 升级。

## 第三步：汇总

逐单结论按「升级 > 驳回 > 需补正 > 通过」取最严：任一阻断级异常模式或二维码不一致 → 升级；任一 ❌ → 驳回；只有 ⚠️ → 需补正（截止为提交日 + 7 个工作日）；全部 ✅ → 通过。

| 置信度 | 条件 |
|---|---|
| 高 | 验真、标准、审批、预算四项都 ✅ |
| 中 | 缺一项辅助材料 |
| 低 | 标准模糊或发票存疑，不得自动通过 |

## 升级条件

- 单笔报销 > 公司档案门槛（默认 10 万元）；
- 假票、失控票，或 ZATCA 二维码与票面不一致；
- 疑似拆单、同票多报、供应商集中；
- 同一员工同一自然月异常 ≥ 3 次；
- 跨季度或跨年度报销。

阈值以 `<company_profile>` 为准；没有时用 `reference/判断框架.md` 的默认值并注明「默认值」。

## 产出（全部是草稿）

- 稽核报告（Excel）：封面与签核页 / 逐单结论 / 逐张票据检查 / 异常模式 / ZATCA 二维码 / 升级事项 / Checks。
- 稽核报告与异常清单（Word）：稽核结论、异常清单、驳回与升级的报销单、发现与建议。
- 稽核结论是预审意见：通过、驳回由财务按制度确认；不付款、不对外发送。

## 输出语言与地区

1. 按调用方给的 `output_language`（zh-CN / en-US / ar）写全部说明文字。
2. 术语使用 `fa-glossary` 的译法（阿语「审计」用 المراجعة）。
3. 不翻译用户数据：科目名称、往来单位、摘要、单号、人名、公司名原样保留。
4. 按调用方给的 `region` 与 `standard` 选择准则与税制；不确定时写「需按当地最新规定核实」，不编造条文号。
