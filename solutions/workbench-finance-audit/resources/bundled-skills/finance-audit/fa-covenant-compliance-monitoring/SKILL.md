# /covenant-compliance-monitoring — Covenant 合规监控


## Examples

→ 示例：用户说"我们的银行贷款有杠杆率 covenant，每个季度需要确认一次合规吗"，系统应调用本技能，执行贷款 covenant 合规性检查。

→ 示例：用户说"最近的 EBITDA 下降可能会触发债务契约，需要提前预警"，系统应调用本技能，执行 covenant 触发风险评估。

→ 示例：用户说"债务契约里有一条限制性分红条款，帮我解释一下对我们股东回报的影响"，系统应调用本技能，解读 covenant 限制条款的影响。

## 第四步：风险评估

**风险分级：**
```
□ 🔴 高风险（任意一项）：
  → 当前值已违反 Covenant
  → 未来 [X] 期内预测将违反且无改善趋势

□ 🟡 中风险：
  → 缓冲空间 < [X]%（如 < 10%）
  → 未来 [X] 期内预测将违反，但有改善可能

□ 🟢 低风险：
  → 缓冲空间充足（> [X]%）
  → 未来 [X] 期内无违约风险
```

**风险驱动因素分析：**
```
□ 主要风险驱动：
  → 风险 1：[描述] — 对 [Covenant] 的影响 [+/-X]x
  → 风险 2：[描述]
```

## 第五步：应对措施

**应对策略选项：**
```
□ 选项 1：保持现状，依赖自然改善
  → 适用条件：风险等级 🟢 或短期风险可自行缓解
  → 风险：缓冲空间可能进一步收窄

□ 选项 2：与银行预先沟通（Consent）
  → 适用条件：风险等级 🟡，预计无法满足但愿意主动沟通
  → 优势：避免被动违约，维护关系
  → 成本：[额外费用/利率上调/额外承诺]

□ 选项 3：提前偿还部分债务
  → 适用条件：有充足现金且划算
  → 效果：直接改善 D/EBITDA 等指标

□ 选项 4： EBITDA 提升措施
  → 适用条件：短期可通过运营改善 EBITDA
  → 措施：[降本/增收]
```

## 升级触发条件

- 当前值已违反或预计未来 [X] 期内违反 Covenant
- 须与银行预先沟通以获取豁免（Consent）
- 风险等级为 🔴 高风险
- 应对措施涉及重大财务决策（提前偿还/资产处置）
- 银行发出违约通知（Event of Default）
- Covenant 违反可能触发交叉违约（Cross Default）
