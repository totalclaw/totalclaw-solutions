# 沙特电子发票（FATOORA）（fa-sa-einvoice）

帮助核对沙特电子发票是否满足 ZATCA 要求，并与增值税申报底稿（`fa-sa-vat-return`）对得上。**不代开发票、不代为上报 ZATCA 平台。**

## 两个阶段

- 第一阶段（生成阶段）：自 2021-12-04 起，发票须由合规的电子系统生成与保存，不得手写或用可编辑文档开具。必备字段见地区规则 `sa.einvoice_required_fields`。
- 第二阶段（集成阶段）：自 `sa.einvoice_phase2_start`（2023-01-01）起由 ZATCA 分批通知纳税人接入，开票系统须与 ZATCA 平台对接：标准税务发票（B2B）先经平台清关再交给买方，简化税务发票（B2C）在规定时间内报送。

## 标准发票与简化发票

| | 标准税务发票（B2B） | 简化税务发票（B2C） |
|---|---|---|
| 对象 | 增值税登记的企业买方 | 个人消费者等 |
| 买方信息 | 买方名称、地址、增值税号 | 一般不需要 |
| 二维码 | 需要 | 需要 |
| 第二阶段处理 | 先清关后交付 | 交付后报送 |

## 二维码（TLV）

简化发票二维码按 TLV（标签-长度-值）编码，再做 Base64。第一阶段的五个基本标签：

1. 卖方名称
2. 卖方增值税号
3. 开票日期与时间
4. 含税总额
5. 增值税额

第二阶段另有发票哈希、数字签名、公钥等标签。核对时把二维码解出的卖方税号、含税总额、税额与票面逐项比对，不一致的列为异常。

## 与申报底稿的核对

- 申报表第 1 栏的税额应能与本期已开具（并已清关 / 报送）的标准税率发票汇总对上。
- 作废、贷项通知单（红字）要按负数计入，原票与红字票都要有记录。

## 升级条件

- 二维码解出的金额或税号与票面不一致：列为高风险，交复核人。
- 第二阶段已接入的纳税人，存在未清关的 B2B 发票：停止申报准备，先查明原因。

## 输出语言与地区

1. 按调用方给的 `output_language`（zh-CN / en-US / ar）写全部说明文字。
2. 术语使用 `fa-glossary` 的译法（阿语「审计」用 المراجعة）。
3. 不翻译用户数据：科目名称、往来单位、摘要、单号、人名、公司名原样保留。
