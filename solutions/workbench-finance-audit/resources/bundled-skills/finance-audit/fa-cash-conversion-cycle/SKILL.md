# 现金转换周期（fa-cash-conversion-cycle）

计算应收、存货、应付三段周转天数与现金转换周期，把天数换成金额，找出最占现金的一段。自建技能（finance-skills README 声明的 working-capital「现金转换周期」能力）。

## 加载上下文

- 期间、本位币、期间天数口径以 `<company_profile>` 与项目上下文为准。
- 阈值与判断规则读 `fa-working-capital-master/reference/判断框架.md`。

## Examples

→ 示例：用户说「算一下我们 9 月的现金转换周期」，调用本技能，按 9 月收入、成本与月末余额计算。

→ 示例：用户说「DSO 比上个月多了 6 天，帮我看看原因」，调用本技能，先算本期与上期 DSO，再列出逾期应收前十的客户。

## 第一步：收集数据

```
□ 期间营业收入：[X]（与期间同口径，月度用当月）
□ 期间营业成本：[X]
□ 期间天数：[30 / 31 / 365]
□ 期末应收未清余额：[X]（来自应收明细）
□ 期末存货余额：[X]（来自存货明细或余额表）
□ 期末应付未清余额：[X]（来自应付明细）
```

收入、成本缺一不可；明细与余额表不一致时先说明差异，不自行调整。

## 第二步：计算

```
DSO = 应收 / 收入 × 天数
DIO = 存货 / 成本 × 天数
DPO = 应付 / 成本 × 天数
CCC = DSO + DIO − DPO
每缩短 1 天 DSO 释放现金 = 收入 / 天数
每缩短 1 天 DIO 释放现金 = 成本 / 天数
每延长 1 天 DPO 保留现金 = 成本 / 天数
```

## 第三步：分析

- 三段里谁拉长了 CCC：与上期或预算比较，变动最大的一段优先分析。
- 应收：列出逾期应收（到期日早于期末）与前十客户。
- 存货：有明细时转 `fa-inventory-optimization` 看呆滞。
- 应付：DPO 明显低于行业或同类供应商的，转 `fa-payables-strategy`。

## 输出模板

```
现金转换周期分析（期间 [YYYY-MM]，草稿）
DSO [X] 天 / DIO [X] 天 / DPO [X] 天 / CCC [X] 天
主要拖累：[应收 / 存货 / 应付]，影响 [X] 天，约占用现金 [X]
建议：[2–3 条，可执行、有负责人]
数据来源：[上传: 文件名 第 N 行] / [工作台计算]
```

## 置信度评估

- 高：收入、成本、余额口径一致，有明细。
- 中：只有余额没有明细。
- 低：收入或成本缺失。

## 升级条件

- CCC 比上期延长 15 天以上，或逾期应收占应收 30% 以上 → 报财务经理。
