# 执行指南 (Execution Guide)

本文档提供详细的执行规范、降级方案矩阵和置信度计算方法，供Agent在执行客户背调时参考。

---

## 一、核心原则

**每个有权重的验证维度都必须有完整的验证步骤和降级方案。**

### 降级策略原则

1. **永不阻塞**：任何验证失败都不应阻止整体流程继续执行
2. **记录状态**：每个步骤的执行方式和结果必须被记录
3. **量化置信**：通过置信度系数反映数据的可靠性
4. **可追溯**：每个判断都有明确的依据和来源

### Phase 1: 基础验证 (权重15%)

#### 1.1 邮箱MX验证

| 方案级别 | 执行方式 | 置信度 | 失败条件 |
|----------|----------|--------|----------|
| **主方案** | `nslookup -type=MX {domain}` | 1.0 | 命令执行失败/无返回 |
| **降级1** | Python `dnspython` 库 | 0.8 | 库未安装/网络错误 |
| **降级2** | 正则验证邮箱格式 | 0.5 | 格式不匹配 |
| **兜底** | 标记"MX未验证" | 0.0 | - |

**执行命令示例**：
```bash
# 主方案
nslookup -type=MX company.com

# 预期输出包含:
# company.com MX preference = 10, mail exchanger = mail.company.com
```

**判断逻辑**：
```
if MX记录存在:
    置信度 = 1.0
    检查域名是否为个人邮箱域名列表中的域名
    if 在个人邮箱列表中:
        邮箱类型 = "个人邮箱"
    else:
        邮箱类型 = "企业邮箱"
        检查域名与公司名匹配度
else:
    执行降级方案
```

#### 1.2 邮箱类型判断

|----------|----------|------|
| 企业邮箱 | 域名匹配公司官网，不在个人邮箱列表 | name@company.com |
| 个人邮箱 | 域名在个人邮箱域名列表 | name@gmail.com |
| 临时邮箱 | 域名在临时邮箱域名列表 | name@tempmail.com |
| 待确认 | 无法明确判断 | name@unknown-domain.com |

**个人邮箱域名列表**（详见 `data/personal_email_domains.txt`）：

#### 1.3 电话格式验证

#### 3.2 姓名匹配规则

```
匹配算法:
1. 标准化处理:
   - 转小写
   - 去除标点符号
   - 展开缩写 (J. → John)

2. 匹配方式:
   a. 完全匹配: "john smith" = "john smith" (得分=100)
   b. 包含匹配: "john smith" contains "john" (得分=80)
   c. 首字母匹配: "j smith" matches "john smith" (得分=70)
   d. 模糊匹配: 编辑距离/余弦相似度 (得分=相似度×100)

3. 多语言处理:
   - 中文名: 张伟
   - 拼音: Zhang Wei / W. Zhang
   - 英文名: David Zhang
   使用拼音转换库进行匹配
```

无论哪种情况，当海关数据为"无数据"时:
- 该维度权重重新分配到其他5个维度
- 不影响其他维度评分

#### 5.3 进口品类匹配

```
匹配流程:
1. 获取客户兴趣产品列表
2. 获取海关记录中的HS编码/产品描述
3. 计算匹配度

匹配度 = 匹配产品数 / 兴趣产品总数

匹配结果:
- 完全匹配 (>80%): 客户进口过同类产品
- 部分匹配 (50-80%): 客户进口过相关产品
- 低匹配 (<50%): 客户未进口过类似产品 ⚠️
- 无数据: 无法判断
```

## 三、置信度计算

### 3.1 数据源可靠性系数

| 数据源类型 | 系数 | 说明 |
|------------|------|------|
| 官方数据库直接访问 | 1.0 | Companies House等官方机构 |
| 官方数据库API调用 | 0.9 | 通过API获取官方数据 |
| 第三方付费API | 0.8 | D&B, Experian等 |
| WebFetch成功 | 0.7 | 直接访问网页获取 |
| WebSearch有结果 | 0.6 | 搜索引擎获取 |
| WebSearch无精确结果 | 0.4 | 搜索结果不精确 |
| 推断/猜测 | 0.3 | 基于逻辑推断 |
| 无法验证 | 0.0 | 验证失败 |

### 3.2 验证深度系数

| 验证深度 | 系数 | 说明 |
|----------|------|------|
| 完整验证 | 1.0 | 所有子项都验证成功 |
| 部分验证 | 0.7 | 部分子项验证成功 |
| 仅存在性确认 | 0.5 | 仅确认存在，无详细信息 |

### 3.3 综合置信度计算

```
维度置信度 = 数据源可靠性系数 × 验证深度系数

维度得分 = Σ (子项得分 × 子项置信度) / 子项数量

总分 = Σ (维度得分 × 维度权重)
```

**计算示例**：
```
公司查询维度 (权重20%):

子项1: 公司注册查询
- 主方案成功, 数据源=官方数据库
- 子项得分: 100
- 置信度: 1.0 × 1.0 = 1.0
- 加权得分: 100 × 1.0 = 100

子项2: 公司状态验证
- 主方案成功, 数据源=官方数据库
- 子项得分: 100 (Active)
- 置信度: 1.0 × 1.0 = 1.0
- 加权得分: 100 × 1.0 = 100

子项3: 注册地址比对
- 降级1成功, 数据源=WebSearch
- 子项得分: 80 (部分匹配)
- 置信度: 0.6 × 0.7 = 0.42
- 加权得分: 80 × 0.42 = 33.6

维度得分 = (100 + 100 + 33.6) / 3 = 77.9
维度加权得分 = 77.9 × 20% = 15.58
```

## 四、常见错误处理

### 4.1 WebFetch拦截

**现象**：访问网站时返回安全拦截或验证码

**处理流程**：
```
1. 检测拦截类型:
   - 安全验证（Cloudflare等）
   - 地区限制
   - 登录要求

2. 执行降级:
   - 降级到WebSearch搜索
   - 尝试其他数据源

3. 记录状态:
   - 标记"主方案失败: 网站拦截"
   - 记录降级方案执行情况
```

### 4.2 WebSearch无结果

**处理策略**：
```
1. 尝试不同关键词组合:
   - 公司全称
   - 公司简称
   - 公司名 + 产品
   - 公司名 + 国家

2. 如果仍无结果:
   - 标记"搜索无结果"
   - 使用更低级别的降级方案

3. 判断是否影响整体评估:
   - 关键维度无数据 → 影响大
   - 非关键维度无数据 → 影响小
```

### 4.3 Python脚本执行失败

**处理流程**：
```
1. 检查错误类型:
   - 库未安装 → 使用pip安装
   - 网络错误 → 降级到其他方案
   - 数据格式错误 → 修改解析逻辑

2. 如果无法修复:
   - 记录错误详情
   - 执行兜底方案
   - 标记"待人工核实"
```
