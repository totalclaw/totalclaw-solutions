# Skill: 通用深度研究（Deep Research）

> 由 `/osint` 命令自动加载（类型：`research`）
> 核心哲学：通用聊天助手给你摘要，我们给你洞察。不是信息搬运工，而是帮客户看见"别人看不见的东西"。

## 与其他 Skill 的区别

| 场景 | 用哪个 Skill |
|------|-------------|
| 调查某家公司 | `osint-company.md` |
| 调查某个人 | `osint-person.md` |
| 对比多个竞品 | `osint-competitor.md` |
| 扫描一个行业 | `osint-industry.md` |
| **研究一个主题/问题/趋势** | **本 skill** |

本 skill 适用于：
- 主题研究（"2026年储能出海趋势"、"宠物智能设备市场机会"）
- 问题解答（"中国DTC品牌在欧洲为什么做不起来"）
- 趋势分析（"关税战对跨境电商供应链的影响"）
- 品类调研（"家用储能电池赛道值不值得做"）
- 策略课题（"如何建立B2B内容营销体系"）
- 任何不适合硬套公司/竞品/行业模板的调研需求

---

## PIR 定义（Priority Intelligence Requirements）

调查开始前，必须先明确 3-5 个核心问题：

```
研究主题：[用户输入的主题/问题]

PIR 清单（基于主题推导）：
1. [核心事实] — 这件事的真实现状是什么？（规模/趋势/关键数据）
2. [驱动因素] — 什么力量在推动/阻碍这个变化？
3. [关键玩家] — 谁在这个领域做得最好？为什么？
4. [风险/机会] — 对我们（客户）来说意味着什么？
5. [行动建议] — 基于以上发现，该怎么做？
```

> 如果用户的问题太宽泛，先缩窄范围再开始。"跨境电商趋势"太大，"2026年关税政策对美国市场家居品类的影响"才是可以出报告的题目。

---

## 研究五步法

```
Step 1: 主题界定与 PIR（搞清楚要回答什么）
Step 2: 多源采集与信源分级（拿到靠谱的数据）
Step 3: 分析框架匹配（选对工具解剖数据）
Step 4: 交叉验证与洞察提炼（找到别人看不见的东西）
Step 5: 结论与行动建议（So What → Now What）
```

---

## Step 1: 主题界定与 PIR

### 1.1 范围界定

- [ ] **主题拆解** — 把用户的大问题拆成 3-5 个可搜索的子问题
- [ ] **边界定义** — 明确：
  - 地理范围（全球 / 美国 / 欧洲 / 中国...）
  - 时间范围（过去12个月 / 未来3年趋势...）
  - 深度要求（快速概览 / 深度分析 / 可执行策略）
- [ ] **输出预期** — 跟用户确认：这份报告给谁看？用来做什么决策？

### 1.2 KIQ 生成

基于用户目标，生成 3-5 个关键情报问题（Key Intelligence Questions）：

```
KIQ 模板：
1. [主题] 的当前市场/行业现状如何？关键指标是什么？
2. 哪些趋势/力量正在改变 [主题] 的格局？
3. [主题] 领域的标杆案例/最佳实践是什么？
4. [主题] 对 [客户业务] 的具体影响是什么？
5. 基于以上发现，最佳行动路径是什么？
```

---

## Step 2: 多源采集与信源分级

### 2.1 采集策略

根据主题类型选择数据源组合：

| 主题类型 | 优先数据源 | 次要数据源 |
|---------|-----------|-----------|
| 市场/行业趋势 | WebSearch 行业报告 + Google Trends | 卖家精灵市场数据（如涉及Amazon） |
| 技术/产品趋势 | WebSearch 技术媒体 + 专利数据库 | SpiderFoot 域名/技术栈扫描 |
| 政策/法规变化 | WebSearch 政府网站 + 行业协会 | SEC EDGAR（如涉及上市公司） |
| 竞争格局 | WebSearch + Hunter.io + 卖家精灵 | ImportYeti 海关数据 |
| 消费者/用户行为 | WebSearch 调研报告 + 社交平台 | Google Trends 需求验证 |
| 供应链/制造 | ImportYeti + 1688 + WebSearch | SpiderFoot 供应商域名扫描 |

### 2.2 搜索模式

每个子问题至少用 3 种搜索角度：

```
角度 1: 直接搜索 — "[主题关键词] 2026 report statistics"
角度 2: 反向搜索 — "[主题] challenges problems failures"
角度 3: 专家搜索 — "[主题] expert analysis opinion [知名媒体/分析师]"
角度 4: 数据搜索 — "[主题] market size revenue growth rate filetype:pdf"
角度 5: 中文搜索 — 同一主题的中文行业报告（视主题而定）
```

### 2.3 信源分级

| 级别 | 信源类型 | 可信度 | 使用方式 |
|------|---------|--------|---------|
| A | 一手数据（官方财报/海关/政府统计） | 高 | 直接引用，作为基准 |
| B | 权威二手（McKinsey/Gartner/行业协会报告） | 中高 | 交叉验证后引用 |
| C | 媒体报道（TechCrunch/行业媒体/新闻） | 中 | 佐证用，不单独作为结论依据 |
| D | 社交/论坛（Reddit/知乎/Twitter） | 低 | 仅用于发现信号和假设，必须验证 |

> **硬规则**: 任何关键结论必须有至少 2 个 B 级以上信源支持。单一来源 = 假设，不是结论。

## Step 3: 分析框架匹配

> 不是每个框架都要用。根据主题自动匹配最相关的 2-3 个框架。

### 框架菜单

| 框架 | 适用场景 | 什么时候用 |
|------|---------|-----------|
| **价值链分析** | 理解利润在产业链各环节的分配 | 品类调研、供应链分析、定价策略 |
| **PESTEL** | 宏观环境对主题的影响 | 政策变化、出海市场、跨国业务 |
| **Porter 五力** | 行业结构性吸引力 | 市场进入决策、竞争分析 |
| **SWOT** | 快速总结优劣势和机会威胁 | 任何需要汇总的场景（通常放在结尾） |
| **BCG 矩阵** | 产品/业务组合定位 | 多产品线分析、投资优先级 |
| **安索夫矩阵** | 增长路径选择 | 扩张策略、新市场进入 |
| **护城河审计** | 竞争壁垒评估 | 竞品分析、投资判断 |
| **Hormozi 价值方程** | 产品/服务的价值评估 | Offer设计、差异化定位 |
| **MVP 验证** | 最小可行验证方案 | 新业务/新市场的行动建议 |
| **机会成本评估** | 决策取舍分析 | 策略选择、资源分配 |

### 框架自动匹配逻辑

```
主题涉及"品类/产业链/定价/利润" → 价值链分析 + PESTEL
主题涉及"市场进入/出海/新市场" → Porter 五力 + 安索夫矩阵 + MVP 验证
主题涉及"竞争/竞品/份额" → Porter 五力 + 护城河审计 + BCG 矩阵
主题涉及"增长/扩张/策略" → 安索夫矩阵 + Hormozi 价值方程 + 机会成本
主题涉及"政策/法规/合规" → PESTEL（加重 P/L 维度）
主题涉及"消费者/用户/需求" → 加载 osint-persona.md 联动
所有主题 → 结尾都附 SWOT 总结
```

### 3.1 价值链分析（Value Chain Analysis）

> 核心问题：从原材料到终端用户，每个环节谁在赚钱？赚多少？为什么？

#### 产业价值链拆解

```
原材料/零部件 → 制造/组装 → 品牌/设计 → 分销/物流 → 零售/终端 → 售后/服务
   ↓              ↓            ↓           ↓            ↓           ↓
 成本占比%      成本占比%     成本占比%    成本占比%     成本占比%    成本占比%
 利润率%        利润率%       利润率%      利润率%       利润率%      利润率%
 关键玩家       关键玩家      关键玩家     关键玩家      关键玩家     关键玩家
```

#### 数据采集

- [ ] **各环节成本/利润** — WebSearch：
  - `"[品类]" manufacturing cost breakdown`
  - `"[品类]" profit margin by channel`
  - `"[品类]" supply chain cost structure`
- [ ] **关键玩家** — 每个环节的头部公司及其市场份额
- [ ] **价值捕获点** — 哪个环节利润最厚？壁垒最高？
- [ ] **价值迁移趋势** — 利润在往哪个环节转移？（DTC趋势 = 品牌吃掉零售利润）

#### 输出格式

```
### 价值链分析

| 环节 | 成本占比 | 典型利润率 | 关键玩家 | 进入壁垒 | 趋势 |
|------|---------|-----------|---------|---------|------|
| 原材料 | X% | X% | [公司] | 高/中/低 | ↑↓→ |
| 制造 | X% | X% | [公司] | 高/中/低 | ↑↓→ |
| 品牌/设计 | X% | X% | [公司] | 高/中/低 | ↑↓→ |
| 分销 | X% | X% | [公司] | 高/中/低 | ↑↓→ |
| 零售 | X% | X% | [公司] | 高/中/低 | ↑↓→ |

**价值捕获洞察**: [哪个环节最赚钱？为什么？你应该在哪个环节切入？]
**价值迁移方向**: [利润在往哪里流？这对你意味着什么？]
```

> **⚠️ So What**: 价值链不是画完就行。必须回答："你应该在哪个环节参与？为什么？"

### 3.2 MVP 验证框架

> 当研究结论指向"值得做"时，附带一个最小验证方案。

```
### MVP 验证方案

**核心假设**: [这件事成立的最关键前提是什么？]

**最小验证方式**:
| 要验证什么 | 怎么验证 | 成本 | 时间 | 成功标准 |
|-----------|---------|------|------|---------|
| [假设1] | [具体方法] | $X | X天 | [指标] |
| [假设2] | [具体方法] | $X | X天 | [指标] |

**Kill Criteria**: [什么信号出现就应该放弃？]
**Scale Criteria**: [什么信号出现可以加大投入？]
```

### 3.3 机会成本评估

> 做这件事 = 不做另一件事。帮客户看清代价。

```
### 机会成本评估

**如果做 [方案A]**:
- 预期收益: [量化]
- 需要投入: [资金/人力/时间]
- 放弃什么: [因为做A而不能做的事]

**如果做 [方案B]**:
- 预期收益: [量化]
- 需要投入: [资金/人力/时间]
- 放弃什么: [因为做B而不能做的事]

**如果什么都不做**:
- 风险: [不行动的代价是什么？]
- 窗口期: [这个机会还能等多久？]

**建议**: [基于以上对比，推荐方案X，原因是...]
```

## Step 4: 交叉验证与洞察提炼

### 4.1 ACH 分析（竞争假设分析）

当数据指向多个可能的结论时，用 ACH 排除：

```
假设 A: [结论1]
假设 B: [结论2]
假设 C: [结论3]

| 证据 | 来源 | 支持A | 支持B | 支持C |
|------|------|-------|-------|-------|
| [数据1] | [来源] | ✓ | ✗ | — |
| [数据2] | [来源] | ✓ | ✓ | ✗ |
| [数据3] | [来源] | ✗ | ✓ | ✓ |

最可能成立的假设: [X]，因为矛盾证据最少。
```

### 4.2 脉弱交叉发现

> 单一数据点没意义，跨维度矛盾才有价值。

```
脉弱检查清单：
□ 公开宣传 vs 实际数据是否一致？
□ 增长趋势 vs 人才流动是否匹配？
□ 市场乐观叙事 vs 基础数据是否矛盾？
□ 头部玩家动作 vs 市场整体方向是否背离？
□ 短期火热 vs 长期结构性支撑是否存在？
□ 中国供应端变化 vs 海外需求端变化是否同步？
```

### 4.3 洞察提炼标准

每个关键发现必须过三道关：

```
1. 信号强度：这个发现有多少独立数据点支持？（≥2个B级来源 = 可用）
2. 独特性：这个洞察是"人人都知道"还是"只有深挖才能发现"？
3. 可行动性：基于这个洞察，客户能做什么具体的事？
```

> 只保留同时满足"有支撑 + 有独特性 + 可行动"的洞察。泛泛的废话不要写。

## 报告风格指南

### 语言风格
- **给结论，不给废话**。"市场规模约$50亿"，不是"根据多方数据综合分析，该市场的规模估计在大约$50亿左右"
- **每段必须有信息增量**。如果删掉一段不影响理解，那就该删
- **用数据说话**。"增长很快"不如"CAGR 23%，2024-2026"
- **敢下判断**。不要两头骑墙。"建议进入"或"不建议进入"，不是"需要进一步研究"
- **承认不知道**。数据不足就说"无法判断，建议通过XX方式验证"，比瞎猜强

### 图表建议
- 趋势数据 → 折线图
- 份额/占比 → 饼图或环形图
- 多维度对比 → 雷达图
- 时间线 → 时间轴
- 流程/链路 → 流程图
- 矩阵分析 → 2×2 象限图
