# Skill: B2B 买家角色画像（Buyer Persona）

> 由 `/osint` 命令自动加载（类型：`persona`）
> 核心哲学：不是画一张"可爱卡片"，而是建一个能驱动销售和产品决策的行为模型。

## 前提条件

本 skill 需要以下输入之一：
- 一份已完成的 OSINT 公司/竞品报告（提供行业+客户画像数据）
- 用户指定的目标行业/产品/客户类型

## PIR 清单

1. **谁在买？** 目标客户的典型角色、职位、组织层级
2. **为什么买？** 驱动采购的核心目标和 KPI
3. **怎么买？** 决策流程、评估标准、信息获取渠道
4. **什么拦住他？** 核心痛点、顾虑、反对理由

## 画像构建五步法

```
Step 1: 数据采集（从公开情报合成）
Step 2: 行为聚类（按目标+行为分群，不按年龄/性别）
Step 3: 画像设计（标准化 Persona 卡片）
Step 4: 验证检查（与已知客户/案例对照）
Step 5: 落地应用（嵌入销售手册 + 触达策略）
```

## Step 1: 数据采集清单

> 不需要问卷和访谈，用 OSINT 公开数据合成。

### 从 OSINT 报告提取

- [ ] **Hunter.io 职位分布** — 目标行业客户公司的职位、部门、层级分布
  - 哪些职位出现频率最高？→ 典型买家角色
  - C-level vs Manager vs Specialist 比例 → 决策层级
- [ ] **招聘 JD 分析** — 目标客户在招什么人？
  - JD 中的 KPI/职责 → 推断买家的核心目标
  - 工具/技能要求 → 推断技术偏好和决策标准
- [ ] **差评痛点结构化** — Trustpilot/Amazon/G2 差评分类
  - 差评主题 → 买家最在意什么
  - 持续 > 3 月的差评 → 行业普遍痛点（非个别问题）
- [ ] **ImportYeti 采购行为** — 进口频次、品类、供应商切换
  - 采购频率 → 预算周期
  - 多供应商 vs 单一供应商 → 采购风格
  - 品类变化 → 需求演变方向

### 行业公开情报

- [ ] **行业论坛/社区** — Reddit, Quora, 行业论坛中的典型讨论
  - 他们在问什么问题？→ 真实痛点
  - 他们推荐什么？→ 决策标准
- [ ] **LinkedIn 内容分析** — 目标行业 KOL/买家发什么内容
  - 热门话题 → 行业关注点
  - 互动最高的帖子 → 情感触发点
- [ ] **竞品客户评价** — G2/Capterra/Trustpilot 正面评价
  - 客户夸什么？→ 买家真正重视的价值
  - 用什么词？→ 你的营销语言库
- [ ] **展会/会议议程** — 行业展会的热门议题和参会者画像
  - 议题趋势 → 行业痛点演变
  - 参会者职位 → 目标触达对象

## Step 2: 行为聚类

> 按目标和行为分群，不按人口统计。

### 聚类维度

| 维度 | 变量 | 数据来源 |
|------|------|---------|
| 核心目标 | 降成本 / 提质量 / 扩渠道 / 合规 / 创新 | 招聘 JD + 差评主题 |
| 决策风格 | 数据驱动 / 关系驱动 / 价格驱动 / 品牌驱动 | 评价内容 + 采购行为 |
| 采购行为 | 高频小单 / 低频大单 / 项目制 / 长期合同 | ImportYeti + 行业特征 |
| 技术成熟度 | 早期尝鲜 / 主流跟随 / 保守观望 | 技术栈 + 招聘工具要求 |
| 组织规模 | S0-S5 对应不同的决策复杂度 | 员工数 + 营收 |

### 分群规则

- 通常产出 **3-5 个主要 Persona**，不超过 5 个
- 每个 Persona 必须在真实客户中能找到至少 3 个对应案例
- 如果两个群体的销售策略相同，合并为一个

## Step 3: Persona 卡片设计

> 每个 Persona 一张标准化卡片，可直接嵌入报告。

### 卡片字段模板

```
## Persona [编号]: [标签名称]
> "[一句典型语录]"

### 基本画像
- **典型职位**: [VP of Procurement / Category Manager / Owner...]
- **组织规模**: [S0-S5 + 员工数范围]
- **行业**: [具体细分]
- **决策权**: [最终决策 / 影响者 / 执行者]
- **预算范围**: [$X - $Y 年采购额]

### 核心目标与 KPI
1. [被考核的第一指标]
2. [第二指标]
3. [第三指标]

### 最大痛点（Top 3）
1. [痛点 + 来源证据]
2. [痛点 + 来源证据]
3. [痛点 + 来源证据]

### 决策旅程
- **触发事件**: [什么让他开始找新供应商？]
- **信息来源**: [去哪里找信息？展会/Google/同行推荐/LinkedIn？]
- **评估标准**: [按什么排序选？价格/质量/交期/认证/关系？]
- **决策周期**: [从了解到签单通常多久？]
- **决策参与者**: [谁还会参与？EB/TG/UB/CH 角色？]

### 购买顾虑与反对理由
1. [可能的反对理由 + 应对策略]
2. [可能的反对理由 + 应对策略]

### 沟通偏好
- **首选渠道**: [邮件 / LinkedIn / 电话 / 展会]
- **内容偏好**: [案例 / 数据 / 视频 / 白皮书]
- **语气风格**: [正式 / 务实 / 技术 / 关系导向]
- **禁忌**: [不要做什么 — 如高压销售、冷电话等]

### 心理纵深层（Psychographic Depth）
> 超越"他做什么"，理解"他为什么这样做"和"怎么打动他"。
> 如已完成 osint-psychograph 分析，从中提取对应此 Persona 的洞察。

- **深层恐惧**: [表面诉求X背后，真正怕的是什么？]
- **核心矛盾**: [他内心最大的A vs B拉扯是什么？]
- **未说出口的渴望**: [他想要但不敢/不好意思说的是什么？]
- **情感触发点**: [什么场景/表达能让他瞬间觉得"说的就是我"？]
- **价值排序**: [当两个价值冲突时，他牺牲哪个保哪个？]

### 价值主张锚点
> 对这类客户，你的核心 pitch 应该是：
> **功能层**: "[解决什么业务问题]"
> **情感层**: "[触达什么心理需求]"
```

## Step 4: 验证检查

完成画像后，执行以下验证：

- [ ] **真实对照** — 能否在已有客户或 OSINT 报告中找到至少 3 个匹配此 Persona 的真实公司/人物？
- [ ] **差异检验** — 不同 Persona 之间的销售策略是否真的不同？（如果相同，合并）
- [ ] **盲区检查** — 是否有已知客户类型不被任何 Persona 覆盖？
- [ ] **反模式标注** — 明确标注"不属于此 Persona"的特征，防止过度泛化

## Step 5: 落地应用

### 与 Sales Playbook 联动

每个 Persona 自动映射到 `osint-sales-playbook.md` 的模块：

| Persona 字段 | 映射到 Playbook 模块 |
|-------------|---------------------|
| 核心目标/KPI | 模块 3: 价值主张设计 |
| 最大痛点 | 模块 4: Pitch Hook |
| 决策旅程 | 模块 5: 触达序列 |
| 购买顾虑 | 模块 6: 异议预判 |
| 沟通偏好 | 模块 5: 渠道选择 |

### 与公司调查联动

当执行 `/osint [公司] company` 时，自动匹配：
- 该公司属于哪个 Persona 类型？
- 对应的沟通策略和价值主张是什么？

## 脉弱交叉分析（Persona 维度）

| 组合 | 逻辑 | 信号 |
|------|------|------|
| 招聘 JD × Persona KPI | JD 强调的指标 = Persona 的核心 KPI | 精准定位买家最在意的价值点 |
| 差评主题 × Persona 痛点 | 行业差评集中在 Persona 的核心痛点上 | 市场普遍未解决 = 你的差异化空间 |
| 采购行为 × 决策风格 | 频繁换供应商 + 价格驱动 | 低忠诚度客户，需要锁定策略 |
| 组织规模 × 决策复杂度 | S3+ 公司 + 多角色参与 | 需要 Buying Committee 策略 |

## 数据源合规约束

- 仅使用公开商业信息构建画像
- 不对个人进行画像（本 skill 面向"角色类型"而非"具体某人"）
- 禁止使用敏感属性（种族、宗教、健康、政治观点）作为聚类维度

## 报告合规声明（每份报告必须追加）

> 本报告基于公开可获取的行业数据、评价平台及商业数据库信息构建，
> 描述的是行业买家"角色类型"而非具体个人。
>
> 仅供商业策略参考，不构成法律意见。
> 数据截止日期：[DATE]，建议每 6-12 个月更新。
> 不得用于个人信用评估、就业决策，不得向第三方出售或转让。
