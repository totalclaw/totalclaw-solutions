# 泰途会议智能管理 更新日志

## 2.0.9 (2026-11-26)

- 恢复 `compat.minAppVersion` 为 `2.0.19`（2.0.8 无新增宿主接口依赖，此前构建脚本自动写成了 `2.0.21` 导致 2.0.19 / 2.0.20 客户端无法升级到 2.0.8）。

## 2.0.8 (2026-11-26)

- 修复部分 Windows 10 电脑本地转写 / 声纹识别必报 `0xC0000005`（语音模型加载异常退出）：内置通用 Python 运行时目录缺少 `msvcp140*.dll`，导致 MSVC 14.44 编译的 `onnxruntime` / `ctranslate2` 回落到旧版 `System32\msvcp140.dll` 触发 `std::mutex` 访问冲突；worker 在 Windows 启动加载原生扩展前改为优先预载同运行时 `_internal` / `native\bin` 随包的 `msvcp140*.dll`，并预载 `sherpa_onnx` 自带的 `onnxruntime.dll` 防 `System32\onnxruntime.dll` 抢占。
- 修复 v2.0.7 遇到 `0xC0000005` 时盲目删除并重下全部 ~1.4 GB 模型的问题：改为先核对本地模型文件 SHA-256，仅重下确实损坏的模型（全部校验通过则跳过重下并在处理日志说明）；强制重下时改为先停占句柄的 worker、待 `.part` 校验通过后再原子覆盖，避免取消或断网误删完好模型。
- 修复切换「在线语音识别」仍受本机声纹 worker 崩溃阻断的问题：在线转写阶段本机声纹提取失败时降级跳过发言人区分（全部归 S1，交主持人分配）。
- 优化语种识别：不加载冗余的声纹模型，已下载 SenseVoice 时优先直接用 SenseVoice 判语种。
- 修复模型 CDN 下载 `WriteStream` 的 `error` 监听器泄漏（消除 `MaxListenersExceededWarning`）、`concatWav16k` 大音频写入背压处理，以及未选择当前身份时挂载首页导致 `home.get` 报错的问题。

## 2.0.7 (2026-11-26)

- 本地转写在模型加载阶段原生崩溃（`0xC0000005` 访问冲突 / `0xC0000409` / `0xC00000FD`）时也触发一次自动修复：加载时只核对文件大小，同样大小但内容被磁盘或杀软改坏的 onnx 会让 onnxruntime 直接崩溃；现在会从 CDN 强制重下（逐文件 SHA-256 校验）后自动重跑。
- 自动「强制重下」修复时，声纹模型 CAM++ 与转写模型一起重下（两者在同一个进程里加载，单看崩溃退出码分不出坏的是哪一个）。

## 2.0.6 (2026-11-26)

- 会议转写 worker 以 `-X faulthandler` 启动：语音模型加载时原生扩展（sherpa-onnx / onnxruntime / kaldi-native-fbank）发生访问冲突（`0xC0000005`）等崩溃时，把崩在哪一行的 Python 调用栈写进处理日志 `detail`（stderr 摘要由 600 字放宽到 2000 字），不再只有一个退出码。

## 2.0.5 (2026-11-26)

- 重新发布 2.0.4 的修正版（2.0.4 首次推送的是「失败后同进程重试」写法，numpy 的 C 扩展同一进程不能加载两次，重试无效；已改为导入前收窄 `sys.path`）。已拿到 2.0.4 的电脑会自动更新到本版。

## 2.0.4 (2026-11-26)

- 会议转写 worker 加载 numpy 增加第二道防线：导入 numpy 前先把 `sys.path` 收窄到解释器自身目录，剔除 `.pth` / 环境变量 / 当前目录等外部注入的路径（里面的同名 `numbers.py` / `numpy.py` 正是 `numpy has no attribute 'short'` 循环导入的来源），即使宿主进程没能带上 `-I` 也不受影响；仍失败时给出「运行时文件被改动 / 安装不完整」的明确提示，处理日志带具体文件路径与 traceback。

## 2.0.3 (2026-11-26)

- 修复部分 Windows 电脑本地语音转写报 `numpy unavailable: partially initialized module 'numpy' has no attribute 'short' (most likely due to a circular import)`：
  - `workerPool` 改用 Python 隔离模式 `-I -X utf8 -B -u` 启动，并清理继承的 `PYTHONPATH` / `PYTHONHOME` / `PYTHONSTARTUP`，彻底隔绝 `%TEMP%`（脚本所在临时目录）、当前工作目录、宿主机全局 Python 环境变量与 user-site 对内置 `numpy` / 标准库的同名遮蔽。
  - `worker.py` 改为先导入内置 `numpy`，再通过 `sys.path.append(pluginsDir)` 追加插件目录（不再 `insert(0)` 抢占标准库与内置包），并在 `numpy` 导入失败时将完整 traceback、`sys.executable`、`numpy.__file__`、`sys.path` 写入处理日志 `detail`。

## 2.0.2 (2026-11-26)

- 配置引导（推荐转写模型、全部本机模型对比表、声纹模型 CAM++）及系统设置 → AI 能力配置中，已下载模型均增加「重新下载」按钮；支持 `force: true` 清理旧的 HF 缓存与残余 `.part` 文件后从 CDN 重新下载校验 SHA-256，并重新核对/补装 Python 语音运行组件。
- 会议录音转写若因语音运行组件缺失（如 `sherpa_onnx` 未装/跨账号缺失）或模型文件缺失/损坏而失败，自动触发一次补装/强制重新下载修复并无缝重跑转写（对缺 VC++ 运行库、杀软拦截 DLL、内存不足等不可通过重下修复的错误则直接给出明确提示，不盲目重下）。
- 未下载声纹模型 CAM++ 时，若本地语音识别 worker 返回 `ready: false`，失败横幅直接透出具体原因（缺运行组件 / 缺 VC++ 运行库 / 模型损坏等），不再只显示笼统的「本地语音识别运行时不可用」。

## 2.0.1 (2026-11-26)

- 会议语音模型（SenseVoice / FireRedASR2 / CAM++ 声纹）改为优先从自建 CDN（`https://cdn2.taituai.com/meeting-models/`）直下，支持 HTTP Range 断点续传与逐文件 SHA-256 校验，权重落盘后自动核对运行组件（失败时兜底宿主通道）；无需更新客户端。
- 模型下载队列与实时进度改由方案主进程持久维护，切换页面 / 关闭再打开配置引导不再重置下载状态，并展示实时进度条。
- 修复本地语音转写/声纹 worker 在 Windows 下的启动隐患：
  - `workerPool` 改为将 Python worker 脚本写入临时 `.py` 文件执行（避免 Windows 下 `-c <18KB 多行脚本>` 的命令行转义与安全软件误拦），开启 Windows stderr GBK 兼容解码。
  - `sherpa-onnx` 与 `onnxruntime` 加载模型前校验文件完整并 `chdir` 到模型目录用纯 ASCII 相对文件名加载，避免 Windows 中文用户名路径导致底层 C++ 直接异常退出。
- 增强报错确认与诊断提示：
  - 按 `spawn` 错误码、Windows NTSTATUS 退出码（缺 VC++ 运行库 `0xC0000135`、指令集不支持 `0xC000001D`、崩溃 `0xC0000005`/`0xC0000409` 等）、信号和 `stderr` 给出明确中文原因与排查/兜底建议（如安装 VC++ 运行库、换 SenseVoice 或切换在线语音识别）。
  - 流水线失败时将 `detail`（退出码、Python 路径、`stderr` 摘要）一并写入主进程日志和会议「处理记录」，声纹采集失败同步透传明确中文原因。

## 2.0.0 (2026-11-17)

需要 TotalClaw 2.0.17 及以上（用到 App 2.0.17 才有的会议转写模型安装与声纹模型管理）。

- 首个方案包版本（runtime.mode=dynamic，hostApi=2）：原先内置在 App 里的会议智能管理工作台迁入方案仓库，界面与主进程逻辑来自方案包，不再随 App 编译。名称「泰途会议智能管理」（旧名「会议智能管理」仍可搜到）。
- 会议 → 纪要 → 任务 → 跟进 → 归档全流程；上传录音（mp3 / m4a / wav / aac / amr / flac / ogg / opus / wma 等）、录屏（mp4 / mov / mkv / avi / flv / wmv / webm 等，自动取音轨）或文字记录（txt / md / docx / srt / vtt / json）。
- 转写：本机 FireRedASR2（内存 ≥ 12GB 时推荐）+ SenseVoice 兜底，按电脑配置推荐、在配置里一键下载；也可以填在线语音识别接口（百炼 / 硅基流动 / OpenAI 兼容）。录音不出电脑（选在线接口时除外）。
- 声纹识别发言人（CAM++，本机）：按停顿切片、只和本场参会人比对；采集同意里包含「确认会议发言后用本人的发言补充声纹」（最多留最近 5 条，只用来补认、不推翻注册声纹的结论，本人可在声纹库关掉）。
- 发言确认与编辑：纪要逐段附原声可播放；待确认时发言人可补全 / 修改本人的段（确认后也行），主持人可改任意段、逐段改发言人；终审、定稿后主持人仍可修错字。
- 执行方案与任务：任务负责人可多位（其中任何一位都能确认方案、复核异议，通知发给每一位）；部门负责人更新进度时给每位任务负责人发「进度更新」通知，点开直达任务。
- 提醒：发言确认超时催办、到期提前提醒、进度跟踪、进度汇总报告，周期可在参数设置里改、改了马上生效；只在 9:00–21:00 发。
- 配置引导：检测电脑配置并推荐转写模型、组织架构（演示 / 导入企微导出的通讯录 / 自建应用同步）、通知推送（自建应用 / 企微群机器人，按手机号或账号 @ 人）、手机端、现场录声纹、大模型连接测试。
- 手机页（企业微信里打开）：首页、会议、任务、项目、我的；声纹采集只录音、绝不录像（https 地址下页面内直接录；局域网 http 时提示用 https 地址打开或用系统录音机）。
