# 人事部 · 招聘（workbench-hr-agent）

人事部（`legion-hr`）的工作台。七步向导 + 候选人看板。

## 可信性规则

- **JD 体检**：正则检查性别、年龄、婚育、户籍地域、民族 / 外貌 / 健康类用词，给出原文；必备条件超过 8 条提示。
- **简历结构化**：姓名、邮箱、电话、公司、学校、技能只收简历原文里出现的。
- **三层筛选**：① 关键词预筛（可选，一个都没命中的直接淘汰，不调模型，可手动改回）② 硬条件门禁：证据必须是简历原话；没有证据只能判「未知」（简历未提及 ≠ 不满足）③ 0–4 锚定打分：没有证据或证据不在简历里的维度按 0 分计并标「需复核」。
- **总分与决定**由程序算：总分 = Σ 权重 × 分数 / 4；必备不满足 → 淘汰；必备未知 → 待定；再按推进线 / 待定线（默认 70 / 50，可改）。
- 邀约邮件：生成草稿 → 人改 → 点「发送邮件」再确认一次才真发（用「设置 → 邮件」配的邮箱，没配走官方代发）；正文里「【请填写】」没补、收件地址不对、已发过都不发。offer 只出草稿，录用由老板拍板。

## 数据

账号目录 `hr-agent/`：岗位与候选人（含简历全文，只存本机）、上传的简历原件、设置（公司名，默认北京泰途科技有限公司；阈值）。

## 已知限制

- 向量预筛未做（只有关键词预筛）；绩效模块（HR8）未做。
- 邮件不直接发送；面试排期未接日历。
- 运营中心大屏上「人事 · 筛选 37/100」这类进度暂不显示（跨方案事件需要宿主支持）。
- 集群分身：主控上批量解析 / 筛选时，模型调用分给本机与在线员工机（worker.run），失败回本机；第 3 步可关。
- 向量预筛：本地字符 n-gram 哈希向量 + 余弦，不调模型、不联网。
- 绩效评估（第 8 步，与岗位无关）：模型只起草目标、给带原文证据的建议分；没分的项不拿 0 分顶、不出等级；上级改过的分优先。
